line art pages and add more over time"), PROJ-04 ("see each page's stage in the pipeline and

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser multipart → filesystem | Artist-supplied page files, with artist-supplied filenames, become files inside the project folder |
| browser → `GET /api/pages/{id}/image` | A page id from the client selects which file's bytes are served back |
| browser → volume/page ids | Row ids from the client select which rows are read, renamed or deleted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-PATH | Tampering | `POST /api/pages` | mitigate | The on-disk name comes from `uploads.save_upload` (UUID plus the format Pillow reported); the client filename reaches only `display_name()` and is stored in `page.original_name` for display. Grep-asserted: every `file.filename` use in the module is wrapped in `display_name(`, and the module contains no `open(` of its own. Proven by `test_upload_stores_a_server_generated_filename`, which uploads `../../evil.png` and asserts nothing lands outside `pages/`. RESEARCH.md Pitfall 3, ASVS L1 V12. |
| T-01-IMG | Denial of Service | `POST /api/pages` | mitigate | Every byte stream goes through `uploads.decode_image`, which runs `Image.open().verify()` in a `try/except` and bounds size, format and dimensions before any processing. A bad file becomes a `RejectedUpload` entry, never an unhandled exception and never a 500. Proven by `test_upload_rejects_a_non_image_with_4xx`. RESEARCH.md Pitfall 4. |
| T-01-SERVE | Information Disclosure | `GET /api/pages/{id}/image` | mitigate | The served path is composed from the current project root plus the server-generated `page.source_path`; the client supplies only an integer row id. The handler resolves the final path and asserts it is inside the project root before returning a `FileResponse`, so the route cannot be turned into an arbitrary-file reader even if the column were ever populated from elsewhere. No filename or path is accepted from the query string. |
| T-01-IDOR | Elevation of Privilege | volume and page ids | accept | There is exactly one artist and one open project, so cross-tenant access has no meaning (ASVS V4 is out of scope per RESEARCH.md § Security Domain). Ids that do not belong to the current project return 404 with neutral copy, which is correctness rather than access control. |
| T-01-DISK | Denial of Service | repeated uploads | accept | Deleting a page or volume leaves its image bytes on disk, so disk use grows monotonically. Accepted for v1: orphaned bytes are recoverable and a deleted page an artist wanted is not, and no v1 requirement asks for reclamation. Bounded per-upload by `MAX_UPLOAD_BYTES` in `uploads.py`. |
| T-01-SQLI | Tampering | routes calling `Store` | transfer | No SQL is constructed here; all access is through `model/store.py`, parameterization mitigated and grep-asserted in plan 01-03. |
</threat_model>
