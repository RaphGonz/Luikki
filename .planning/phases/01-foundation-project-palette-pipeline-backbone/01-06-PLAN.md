<objective>
Stand up the FastAPI layer's contracts and shell: every request/response DTO the phase
needs, the per-request `Store` dependency, the single upload-validation choke point, the
project-folder layout constants, the app factory with all seven routers registered, and a
`comiccolor serve` entry point.

Six of the seven routers are registered as empty stubs here on purpose. Plans 01-07
through 01-10 fill exactly one router module each, which is what lets them run in parallel
without three plans editing `app.py` and `schemas.py` at once.

Purpose: 01-PATTERNS.md is blunt that this whole layer is greenfield — "no analog anywhere
in this repo (first web code this project has ever had)". RESEARCH.md Patterns 1 and 2 and
its § Code Examples are the authoritative sources, not an in-repo analogy. Getting the
contract layer right once, up front, is what stops the four route plans from each inventing
their own error shape, their own upload handling and their own connection lifecycle.

Output: `src/comiccolor/web/` complete except for six router bodies, plus `comiccolor serve`.

**Discretion calls made here, stated explicitly rather than left implicit:**
- **"Currently open project" is global per process** (`app.state.current_project_path`),
  not per session. RESEARCH.md Pitfall 2 asks the planner to decide this consciously:
  PROJECT.md's constraint is one machine, one artist, supervised over video call, so a
  process-global is correct and sufficient. The residual risk (two browser tabs pointed at
  two projects) is accepted for v1 and recorded in the threat register.
- **No ORM.** The existing `Store` stays the data layer, per CONTEXT.md's discretion note.
- **Pydantic DTOs are separate classes from the `model/entities.py` dataclasses**, not
  reuses of them (01-PATTERNS.md: validation semantics differ materially).
</objective>

**`appconfig.py`** — the project-folder layout and the recents index, with no new dependency
(RESEARCH.md § Supporting explicitly recommends against `platformdirs` for a Windows-only v1).

Constants: `PROJECT_DB_NAME = "project.db"`, `PAGES_DIR = "pages"`,
`REFERENCES_DIR = "references"`, `PENDING_DIR = "references/pending"`,
`LABEL_MAPS_DIR = "label_maps"`, `CONFIG_DIR = Path.home() / ".comiccolor"`,
`RECENTS_PATH = CONFIG_DIR / "recent.json"`, `DEFAULT_WORKSPACE = Path.home() / "ComicColor"`,
`MAX_RECENTS = 10`.

`@dataclass(frozen=True) class RecentProject {name: str, path: str, opened_at: str}`.

`create_project_folder(parent: Path, name: str) -> Path` — creates
`<parent>/<name>/` plus `pages/`, `references/pending/` and `label_maps/`, and raises
`FileExistsError` if a `project.db` is already there. This is D-04's layout, and it is what
makes a project portable by copying the folder.

`is_project_folder(path: Path) -> bool` — the path exists, is a directory, and contains
`project.db`.

`read_recents() -> list[RecentProject]` — reads `RECENTS_PATH`, tolerates a missing or
corrupt file by returning an empty list, and **filters out every entry whose folder no
longer passes `is_project_folder`**. D-04 is explicit that the index is a convenience only
and must never be authoritative over the folder; silently dropping vanished entries is what
enforces that.

`record_recent(path: Path, name: str) -> None` — upsert to the head of the list, dedupe by
resolved path, cap at `MAX_RECENTS`, create `CONFIG_DIR` if needed, write atomically
(write to a temp file in the same directory, then replace). `forget_recent(path) -> None`
for completeness.

**`deps.py`** — RESEARCH.md Pattern 1, essentially verbatim.

`NO_PROJECT_DETAIL = "No project is currently open."`

`get_current_project_path(request: Request) -> Path` — reads
`request.app.state.current_project_path`, raising `HTTPException(409, NO_PROJECT_DETAIL)`
when unset.

`get_store(project_path: Path = Depends(get_current_project_path)) -> Iterator[Store]` —
`with Store(project_path / PROJECT_DB_NAME) as store: yield store`. A fresh connection per
request is what reconciles `Store`'s documented "one Store per thread" with FastAPI running
sync routes on a threadpool; a shared global connection with `check_same_thread=False` is
explicitly rejected by RESEARCH.md § Alternatives Considered as a race-condition risk.
Re-running the idempotent `CREATE TABLE IF NOT EXISTS` script per request costs microseconds
on a local file and is immaterial at one-artist scale.

`get_project(store: Store = Depends(get_store)) -> Project` — returns `store.the_project()`,
raising `HTTPException(409, NO_PROJECT_DETAIL)` if the database has no project row.

`set_current_project(app: FastAPI, path: Path) -> None` and
`clear_current_project(app: FastAPI) -> None` — the only two places
`app.state.current_project_path` is ever written. Document at the top of the module that
this is process-global by conscious choice (PROJECT.md: one machine, one artist, supervised
session), that RESEARCH.md Pitfall 2 and Assumptions Log A2 record the accepted residual
risk of two tabs pointing at two projects, and that nothing else may mutate that attribute.

**`uploads.py`** — the single place untrusted bytes become a file on disk.

`UPLOAD_ERROR_DETAIL = "Upload failed: the file isn't a readable image — try a PNG, JPG or TIFF."`
(verbatim from 01-UI-SPEC.md's Copywriting Contract — the frontend renders this string as-is,
so it must not be paraphrased).
`MAX_UPLOAD_BYTES = 64 * 1024 * 1024`, `MAX_DIMENSION = 20000`,
`ALLOWED_FORMATS = {"PNG": ".png", "JPEG": ".jpg", "TIFF": ".tif", "BMP": ".bmp", "WEBP": ".webp"}`.

`decode_image(data: bytes) -> Image.Image` — rejects oversized payloads, runs
`Image.open(BytesIO(data)).verify()` inside a `try/except Exception`, re-opens the bytes
afterwards (`verify()` leaves the object unusable), rejects a `format` outside
`ALLOWED_FORMATS` and any dimension above `MAX_DIMENSION` or below 1, and raises
`HTTPException(400, UPLOAD_ERROR_DETAIL)` for every failure. Nothing downstream ever sees a
Pillow exception — RESEARCH.md Pitfall 4's whole point is that "the app crashed" in front of
an artist on a video call is the realistic failure mode.

`@dataclass(frozen=True) class SavedUpload {path: Path, relative_path: str, width: int, height: int, format: str}`.

`save_upload(data: bytes, dest_dir: Path, project_root: Path) -> SavedUpload` — decodes and
validates first, then writes to `dest_dir / f"{uuid4().hex}{ALLOWED_FORMATS[fmt]}"`. The
filename is **server-generated from a UUID and the format Pillow reported**, never from
`UploadFile.filename` — RESEARCH.md Pitfall 3. `relative_path` is the path relative to
`project_root`, which is what goes into `page.source_path` so the project folder stays
portable when copied (D-04). Assert with a comment that `dest_dir` is always built from
`appconfig` constants and never from request data.

`display_name(filename: str | None) -> str` — strips every directory component using both
`PurePosixPath(...).name` and `PureWindowsPath(...).name`, trims whitespace, truncates to a
sane length, and falls back to `"untitled"`. This value is for display only and goes to
`page.original_name`; it must never be joined into a path. Say so in the docstring.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → FastAPI `/api/*` | Every JSON body, query parameter and multipart part crosses here untrusted |
| multipart bytes → filesystem | Uploaded file contents become files inside the artist's project folder |
| request → `project.db` selection | Which database a request writes to is resolved from process state, not from the request |
| FastAPI → `Store` SQL | Values reach parameterized statements owned by `model/store.py` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-PATH | Tampering | `web/uploads.py:save_upload` | mitigate | The on-disk name is `uuid4().hex` plus an extension derived from the format Pillow itself reported; `UploadFile.filename` never reaches path construction (grep-asserted to be absent from the module). The artist-visible name goes through `display_name`, which strips both POSIX and Windows directory components and is documented as display-only. `dest_dir` is always composed from `appconfig` constants, never from request data. RESEARCH.md Pitfall 3, ASVS L1 V12. |
| T-01-IMG | Denial of Service | `web/uploads.py:decode_image` | mitigate | `Image.open(...).verify()` runs inside a `try/except Exception` before any processing; payloads over `MAX_UPLOAD_BYTES`, formats outside `ALLOWED_FORMATS`, and dimensions outside `1..MAX_DIMENSION` are all rejected with a 400 carrying the UI-SPEC error sentence. `EmptyImageError` from the extractor is mapped to 400 by an app-level handler. No Pillow or OpenCV exception can surface as a 500. RESEARCH.md Pitfall 4. |
| T-01-DB | Tampering | `web/deps.py:get_store` | mitigate | The database path is resolved only from `app.state.current_project_path`, written only by `set_current_project`/`clear_current_project` in `deps.py` (grep-asserted). No request field names a database. A request with no project open gets a 409 rather than a default or a guess — proven by `test_requests_without_an_open_project_return_409`. RESEARCH.md Pitfall 2. |
| T-01-TABS | Tampering | process-global current project | accept | Two browser tabs open on two projects would share one process-global path and could write to the unintended project. Accepted for v1: PROJECT.md constrains the product to one machine, one artist, in a supervised session, and RESEARCH.md Assumptions Log A2 records the same judgement. Revisit if HOST-01 (multi-user hosting, v2) is ever taken up. |
| T-01-SQLI | Tampering | routers calling `Store` | mitigate | Routers never build SQL. Every database access goes through `model/store.py`, whose 100% parameterization is enforced and grep-asserted in plan 01-03 (`T-01-SQLI`). 01-PATTERNS.md § Shared Patterns makes this a cross-cutting rule for every new Python file in this phase. |
| T-01-NET | Information Disclosure | `comiccolor serve` bind address | mitigate | `--host` defaults to `127.0.0.1`, asserted by a grep for the absence of `0.0.0.0`. The app has no authentication by design (ASVS V2 out of scope per PROJECT.md), so binding to a routable interface would expose an unauthenticated file-writing API to the local network. |
| T-01-INPUT | Tampering | JSON request bodies | mitigate | Every body is a Pydantic model with typed fields, enum-constrained stage values, `0..255`-bounded RGB channels and length-bounded strings — FastAPI rejects anything else with a 422 before a handler runs. ASVS L1 V5. |
