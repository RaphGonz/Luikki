<objective>
Wave 0 for the frontend, plus the first of the phase's three foundation primitives.

Stand up the greenfield `frontend/` project (Vite + TypeScript + Vitest, no component
framework), encode 01-UI-SPEC.md's token tables as CSS custom properties, and ship the
shared screen<->label-map coordinate transform with unit tests at both zoom extremes.

Purpose: the ROADMAP phase goal names the coordinate transform as one of three
primitives that must exist *before* an editor does, "since retrofitting them after an
editor exists is far costlier than building them first". It has no consumer in Phase 1
by design — Phases 2 and 3 route every click, hover and freehand stroke through it, and
`.planning/research/PITFALLS.md` Pitfall 7 is specifically about what happens when each
editor rolls its own. Building it here, alone, tested, is the point.

Output: a buildable, testable `frontend/` project; `frontend/src/geometry/transform.ts`;
`frontend/tests/transform.test.ts`.

**Ownership decision, stated explicitly as CONTEXT.md's discretion note requires:** the
transform lives in **TypeScript**, not Python. Its only consumers are the browser-side
Konva editors in Phases 2–3; a click hit-test must resolve without a network round trip,
and stretching one abstraction across the language boundary would put the authoritative
maths a fetch away from the interaction that needs it. If the server ever has to rasterise
a client-sent polyline, that is a separate small Python function with its own tests, not a
shared abstraction.
</objective>

Create `frontend/src/geometry/transform.ts` exporting `Point`, `Viewport`,
`screenToLabelMap` and `labelMapToScreen` with the signatures and bodies given in
RESEARCH.md Pattern 6.

`Viewport` fields: `zoom` (screen px per label-map px), `panX`, `panY` (screen-space
offset of the viewport origin), `devicePixelRatio`, and `panelOffset: Point` (the panel
bbox origin in page-pixel space).

`screenToLabelMap` divides out `zoom * devicePixelRatio`, subtracts `panelOffset`, and
returns `Math.floor`-ed integer coordinates. `labelMapToScreen` is its inverse without
flooring (screen space is continuous).

`Math.floor` rather than `Math.round` is deliberate and must be stated in the module
docstring: NumPy indexes a label map with floor-based pixel binning, so rounding here
would make a click one sub-pixel from a region boundary resolve to a different region on
the client than on the server. Cite `src/comiccolor/model/masks.py` for the convention
being matched, and PITFALLS.md Pitfall 7 for why this module is the single implementation.

Also state in the module docstring that this module has **no consumer in Phase 1** and
is built ahead of the Phase 2/3 editors on purpose, and that `Viewport` is expected to
gain fields when real usage reveals them — extending it later is fine, forking it is not.

No DOM access, no imports at all. Complete type annotations on every export.

Create `frontend/tests/transform.test.ts` using Vitest's `describe`/`it`/`expect`.

Cover, at minimum:
  - **Identity viewport** — `zoom: 1`, `panX: 0`, `panY: 0`, `devicePixelRatio: 1`,
    `panelOffset: {x: 0, y: 0}`: a screen point maps to the same label-map coordinate.
  - **Round trip at extreme zoom-in** (`zoom: 64`) and **extreme zoom-out**
    (`zoom: 0.05`): `screenToLabelMap(labelMapToScreen(p, vp), vp)` returns `p` for a
    set of integer label-map points including `{x: 0, y: 0}` and a large one. This is
    Pitfall 7's explicit requirement and both extremes must be present as separate cases.
  - **devicePixelRatio 2** — a HiDPI viewport halves the label-map delta for the same
    screen delta.
  - **panelOffset** — a non-zero panel bbox origin shifts label-map coordinates by
    exactly that offset and cancels on the round trip.
  - **Floor, not round** — a screen point that lands at label-map 3.99 resolves to 3,
    and one at 4.0 resolves to 4. Assert `screenToLabelMap` never returns a
    non-integer: `Number.isInteger` holds for both components.
  - **Negative coordinates** — a point above/left of the panel origin floors toward
    negative infinity (-0.5 becomes -1, not 0), matching NumPy, not C truncation.

Use exact `toBe`/`toEqual` equality where the maths is exact; use `toBeCloseTo` only in
the continuous `labelMapToScreen` direction where floating-point drift is real.

Every `it` title states the guarantee being pinned, matching the house convention of
docstrings that say what design property a test proves.
  </action>
