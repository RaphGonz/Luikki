<objective>
Implement the project lifecycle: create, open, close, current, recent and browse.

This is PROJ-01 ("create a named project and reopen it later with its pages, palette and
edits intact") and the durable half of PROJ-05, expressed as HTTP.

Purpose: D-04 makes a project a folder the artist names, with `project.db` inside it, so
that copying, moving, backing up or handing over the folder just works — which matters
directly for the supervised video-call testing model. That promise only actually holds if
closing a project checkpoints the WAL, which is why the user's resolution of RESEARCH.md
Open Question 1 made checkpoint-on-close mandatory rather than optional.

Output: a complete `web/routers/project.py` and a green `tests/test_web/test_project_routes.py`.

**Folder-picking design, stated explicitly.** A browser cannot hand a server an arbitrary
local folder path: `<input type="file" webkitdirectory>` deliberately strips absolute paths.
Since the browser and the server are the same machine by hard constraint, the correct native
picker is a host-side dialog. `POST /api/projects/browse` opens
`tkinter.filedialog.askdirectory()` (stdlib, no new dependency) on the host and returns the
path the artist explicitly chose; if tkinter is unavailable or the dialog fails it returns
503 and the frontend falls back to the recent-projects list plus a typed path, which goes
through the same validation. The security control is not "the path came from a dialog" —
it is that `POST /api/projects/open` opens nothing that does not resolve to a real directory
containing `project.db`.
</objective>

`_resolve_project_path(raw: str) -> Path` — the single validator every path-accepting route
uses. It expands `~`, calls `Path(raw).resolve()`, and raises
`HTTPException(400, NOT_A_PROJECT_DETAIL)` unless `is_project_folder` returns True. It must
never create anything and never follow a caller's path into a `mkdir`. Docstring cites
RESEARCH.md § Security Domain V12: the backend does not blindly trust a path string.

`POST /` -> 201 `ProjectResponse`. Takes `ProjectCreateRequest`. Resolves the parent as
`Path(body.parent_dir).expanduser().resolve()` when supplied, else `DEFAULT_WORKSPACE`
(created if absent). Calls `create_project_folder(parent, body.name)`, mapping
`FileExistsError` to `HTTPException(409, PROJECT_EXISTS_DETAIL)`. Opens a `Store` at
`<folder>/project.db` (which creates the schema), inserts the single `Project` row via
`add_project`, then `checkpoint()` and closes it. Calls `set_current_project(request.app, folder)`
and `record_recent(folder, body.name)`. Returns the project with its folder path.

This route builds its own `Store` explicitly rather than using `Depends(get_store)` —
`get_store` resolves the *already open* project, and at create time there is not one yet.
Say so in a comment so a later contributor does not "simplify" it into the dependency.

`POST /open` -> 200 `ProjectResponse`. Takes `ProjectOpenRequest`, runs `_resolve_project_path`,
opens a `Store` to read `the_project()`, raises `HTTPException(400, NOT_A_PROJECT_DETAIL)`
when the database has no project row, then `set_current_project` and `record_recent`.

`GET /current` -> 200 `ProjectResponse`, using `Depends(get_project)` so a missing open
project yields the shared 409 rather than a route-local special case. Include the folder
path in the response — 01-UI-SPEC.md §8 shows the project name in the top toolbar, and the
picker needs the path to highlight the matching recent row.

Every route is a sync `def` (they do blocking SQLite and filesystem work; FastAPI runs sync
routes on its threadpool, which is exactly what the per-request `Store` design in
RESEARCH.md Pattern 1 is built for). Do not mark them `async def` and then block inside.

`POST /close` -> 204. Resolves the current project path (404/409 semantics via
`get_current_project_path`), opens a `Store` on it, calls `store.checkpoint()`, closes it,
then `clear_current_project(request.app)`. The checkpoint is the point of the route: WAL mode
keeps recently committed rows in `project.db-wal`, and D-04 promises the artist can copy,
zip or hand over the folder and have it work. Without the truncating checkpoint that promise
is not kept. The route docstring must say exactly that and cite RESEARCH.md Pitfall 1 and the
resolved Open Question, so nobody later removes it as redundant with `Store.close()`.

`GET /recent` -> 200 `list[RecentProjectResponse]`, straight from `read_recents()`, most
recent first. Because `read_recents` already drops entries whose folder no longer contains
`project.db`, a project the artist moved or deleted outside the app simply disappears from
the list — the index never claims authority over the filesystem (D-04). Do not "repair" or
re-create a missing folder.

`POST /browse` -> 200 `BrowseResponse` or 503. Opens a native folder dialog on the host with
`tkinter.filedialog.askdirectory()`, run inside a hidden, immediately-destroyed `Tk` root, and
wrapped in `try/except Exception` so a headless or tkinter-less environment returns
`HTTPException(503, BROWSE_UNAVAILABLE_DETAIL)` rather than a 500. A cancelled dialog
(empty string) returns 204 with no body. Import `tkinter` lazily inside the function so
importing the router never requires a display.

The dialog is native and host-side because the browser and the server are the same machine
by PROJECT.md constraint; a browser directory input deliberately strips the absolute path,
so there is no client-side way to satisfy D-04's folder-pick model. Record in the docstring
that the actual security control is `_resolve_project_path` on `POST /open`, not the
provenance of the string — the picker is an ergonomics feature, and the frontend's typed-path
fallback goes through the same validator.

Do **not** persist a "vouched paths" allowlist or a single-use browse token. For a
single-user local app where the caller already owns the process, that machinery adds state
without changing the actual trust boundary; the residual risk is recorded in the threat
register instead.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `POST /api/projects/open` | A filesystem path string arrives from the client and determines which database the process opens |
| browser → `POST /api/projects` | A project name and parent directory determine where a folder is created |
| host OS dialog → server | `tkinter.filedialog` returns a path chosen interactively on the host |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-OPEN | Information Disclosure | `POST /api/projects/open` | mitigate | Every path goes through `_resolve_project_path`, which resolves symlinks with `Path.resolve()` and refuses anything that is not an existing directory containing `project.db`. It never creates, never `mkdir`s and never follows the caller's path into a write. A non-project path returns 400 with the UI-SPEC error sentence, disclosing nothing about the filesystem beyond "not a project". ASVS L1 V12; pinned by `test_open_rejects_a_path_without_a_project_db`. |
| T-01-CREATE | Tampering | `POST /api/projects` | mitigate | Folder creation goes through `appconfig.create_project_folder`, which composes the path from a resolved parent plus a single name component; the module contains no `mkdir` of its own (grep-asserted). An existing `project.db` in the target yields 409 rather than being overwritten, so a create can never clobber an artist's project. |
| T-01-BROWSE | Denial of Service | `POST /api/projects/browse` | mitigate | `tkinter` is imported lazily inside the handler and the whole dialog is wrapped in `try/except Exception`, returning 503 with actionable copy on a headless or tkinter-less host. Importing the router never requires a display, so a broken dialog cannot take the app down at startup. |
| T-01-LOCALPATH | Information Disclosure | typed-path fallback in the frontend | accept | On a single-machine, single-artist app the caller already owns the process and its filesystem, so a free-text path is not a privilege boundary — the realistic failure is a typo, which `_resolve_project_path` turns into a 400. RESEARCH.md § Security Domain prefers a native dialog and `POST /browse` provides one; the residual case is accepted rather than defended with a vouched-path allowlist that would add state without moving the boundary. |
| T-01-DUR | Denial of Service | `POST /api/projects/close` | mitigate | The close route checkpoints the WAL with `PRAGMA wal_checkpoint(TRUNCATE)` so a folder copied straight afterwards is a complete database. Asserted by `test_close_checkpoints_the_wal`, which copies the folder and reopens it. RESEARCH.md Pitfall 1. |
| T-01-SQLI | Tampering | routes calling `Store` | transfer | No SQL is constructed here; every access is through `model/store.py`, whose parameterization is mitigated and grep-asserted in plan 01-03. |
</threat_model>
