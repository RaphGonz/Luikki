<objective>
Build the palette extractor that serves both PAL-01 (swatch image) and PAL-02
(character sheet), as one function with a sheet-aware pre-pass.

Purpose: D-12 settles that the palette is built by dominant-colour extraction over the
whole image, not by chip/contour detection — explicitly overriding
`.planning/research/STACK.md`'s `cv2.findContours`/`connectedComponents` proposal for this
requirement. D-13 requires integrating an existing library rather than hand-rolling, and
RESEARCH.md's live verification found that Pillow's own `Image.quantize()` recovers a flat
chip grid exactly at zero new dependency — which D-13 names as a legitimate winning
outcome. D-15 requires the count to be adaptive, and none of the four candidate libraries
does adaptive count, so the merge pass on top is the genuinely project-specific 10%.

Output: `src/comiccolor/colour/extract.py` and a green `tests/test_extract.py`.

**Library decision, recorded here so no later plan re-litigates it:** Pillow's
`Image.quantize(colors=K_MAX, method=MEDIANCUT, dither=NONE)` for the solved part, plus a
small CIELAB merge using `skimage.color.rgb2lab` / `deltaE_cie76` for the adaptive count.
Pylette 6.0.0 (MIT, actively maintained, KMeans) is the documented swap-in if median cut
proves visibly worse on real photographed character sheets — the merge logic above it is
unaffected either way. ColorThief is rejected on maintenance grounds and colorgram.py adds
a dependency for what `getcolors()` already returns. This is RESEARCH.md § Standard Stack
and § Alternatives Considered, verified live against PyPI.
</objective>

`extract.py` defines five module-level constants, each with a comment stating it is an
unvalidated starting value to be tuned against real artist uploads (RESEARCH.md Pitfall 5 —
these must never quietly become spec):
  - `K_MAX = 24` — the generous quantization ceiling. The adaptive count is what survives
    the merge, never this number.
  - `MERGE_DELTA_E = 12.0` — CIELAB `deltaE_cie76` below which two clusters are the same
    colour. The comment should note that Phase 5's snapping threshold is the same *kind* of
    constant and that `.planning/research/PITFALLS.md` Pitfall 10 already warns about this
    exact class of number hardening into spec.
  - `MIN_PIXEL_SHARE = 0.005` — clusters holding under 0.5% of kept pixels are extraction
    noise and are dropped.
  - `INK_MAX = 30` and `PAPER_MIN = 235` — the near-black and near-white bounds for D-14's
    sheet pre-pass.

`@dataclass(frozen=True) class ExtractedColour` with `rgb: tuple[int, int, int]`,
`pixel_count: int`, `pixel_share: float`.

`class EmptyImageError(ValueError)` — raised when the image has no pixels or nothing
survives the pre-pass, so the web layer can turn it into a structured 4xx rather than an
IndexError.

`def extract_palette(image: Image.Image, *, sheet_mode: bool = False) -> list[ExtractedColour]`:
  1. Convert to `RGB` (flattening any alpha over a fixed mid-neutral background), because
     `MEDIANCUT`/`MAXCOVERAGE` do not accept RGBA — RESEARCH.md Pattern 3's stated caveat.
  2. If `sheet_mode`, run `_drop_ink_and_paper` first (Task 2 adds it).
  3. `_quantize_counts`: call `image.quantize(colors=K_MAX, method=Image.Quantize.MEDIANCUT, dither=Image.Dither.NONE)`
     then `.convert("RGB").getcolors(maxcolors=256)` to get `(count, rgb)` pairs.
  4. `_merge_similar`: convert every cluster RGB to CIELAB with `skimage.color.rgb2lab`,
     then merge greedily — walk clusters in descending pixel count and fold any later
     cluster whose `deltaE_cie76` to an already-kept cluster is below `MERGE_DELTA_E` into
     that cluster, summing pixel counts and keeping the larger cluster's RGB, so a flat chip
     is never shifted by its own anti-aliased edge pixels.
  5. Drop clusters whose share of the total kept pixels is below `MIN_PIXEL_SHARE`.
  6. Return the survivors sorted by descending `pixel_share`, with `pixel_share` computed
     against the total kept pixel count.

Do **not** implement k-means, median cut, RGB-to-Lab conversion or a colour-distance
formula by hand (D-13, RESEARCH.md § Don't Hand-Roll). Do **not** resurrect
`cv2.findContours` / `connectedComponentsWithStats` chip detection — D-12 overrides it and
RESEARCH.md § Anti-Patterns names it explicitly.

Do **not** take a colour-count argument. D-15 is that the extractor decides; the artist's
recovery lever is PAL-03's manual add and delete, reachable from the same screen as the
result (01-UI-SPEC.md §4), not a count slider.

Module and function docstrings in `manga_line.py`'s voice: state why quantize-plus-CIELAB-
merge was chosen over chip detection (citing D-12/D-13), name the accepted weakness openly
(median cut is coarser than KMeans on a genuinely photographed, shaded sheet — D-15 accepts
this class of imperfection and PAL-03 is the recovery path), and flag `MERGE_DELTA_E` as
tunable rather than settled.

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-01-IMG | Denial of Service | `extract_palette` decoding an artist-supplied image | mitigate | `extract_palette` takes an already-decoded `PIL.Image.Image`, never raw bytes or a path, so decoding of untrusted bytes happens exactly once at the HTTP boundary in `web/uploads.py` (plan 01-06), where `Image.open().verify()` and dimension bounds are enforced and a structured 4xx is returned. This module's only failure mode on degenerate input is `EmptyImageError`, which is a `ValueError` subclass the router maps to 400 — never an unhandled exception surfacing as a 500 (RESEARCH.md Pitfall 4). | T-01-MEM | Denial of Service | `_drop_ink_and_paper` building an `N x 1 x 3` array of kept pixels | mitigate | The kept-pixel array is bounded by the source image's pixel count, which plan 01-06's upload validator caps before this function is ever reached. `quantize` runs at a fixed `K_MAX = 24` regardless of input size, so no input-controlled loop bound exists. |
| T-01-SC | Tampering | `scikit-image` import | mitigate | Declared and audited in plan 01-01 (RESEARCH.md § Package Legitimacy Audit, `Approved`, 10+ years on PyPI, official scikit-image org). Already present as an undeclared transitive dependency, so this phase reduces supply-chain ambiguity rather than adding to it. |
| T-01-CONST | Tampering | `MERGE_DELTA_E`, `INK_MAX`, `PAPER_MIN` | accept | These are unvalidated hypotheses (RESEARCH.md Assumptions Log A1). A wrong value degrades proposal quality, not safety; PAL-03's manual add and delete is the accepted recovery path (D-15). Mitigated against silent hardening by being named constants with unvalidated comments and by `test_thresholds_are_named_constants`. |
