<objective>
Wire the browser to the Phase 2 API: DTO types that mirror the server's models, one client method
per endpoint, and the `#/page/{id}/edit` route the editor screen mounts on.

Purpose: Phase 1 established that the frontend never constructs a filesystem path and never
hand-builds a URL — `apiUrl` and the `api` object are the single seam. Phase 2 adds thirteen
endpoints, and every one of them has to arrive through that same seam or the seam stops being one.

Output: the typed client surface plan 02-13's view consumes.

Supports D-19 (the list-returning mutation shape is what makes routine deletion cheap on the
client), D-20 (mask methods are page-scoped, never panel-scoped) and D-26 (no new dependency —
this is `fetch` and types).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| location hash → route dispatch | A URL fragment the artist can be handed by anyone decides which view mounts and which id it queries |
| server JSON → typed DTO | Response bodies are trusted as shaped; a mismatch surfaces as a runtime undefined rather than an exception |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-37 | Tampering | Malformed page id in the hash | mitigate | `parseRoute` keeps Phase 1's integer validation and picker fallback (T-01-HASH) for the new `edit` form; a bad id never reaches the API, and an id that does reach it answers a neutral 404 from the routers |
| T-2-38 | Tampering | A view hand-building an API URL | mitigate | Every new call goes through `apiUrl` inside the `api` object; `client.test.ts` asserts each method's URL, so a hand-built URL elsewhere would bypass a tested seam and is visible in review |
| T-2-09 | Tampering (XSS) | Server strings rendered by the view | transfer | The `GoBackTargetDto` strings are server-computed and rendered with `textContent` by plan 02-14's dialog; this plan only types them |
| T-2-21 | Tampering | Client-side geometry validation | transfer | The client sends whatever the editor produced; `Polygon`/`PixelCoord` re-validate server-side (plan 02-05). No duplicate validation is added here, so there is no second definition to drift |
</threat_model>
