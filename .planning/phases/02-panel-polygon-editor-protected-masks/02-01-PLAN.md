  </read_first>
  <action>
    Create `tests/conftest.py` (new, root-level — none exists today) exporting three pure
    builder functions usable both as plain imports and as fixtures:

    - `glyph_row(page, x, y, count=6, glyph_w=8, glyph_h=12, gap=5)` — writes `count`
      baseline-aligned dark blobs of identical height into a boolean array. This is the
      positive case D-23's height/baseline/aspect filters must accept.
    - `bubble_page(width=600, height=400)` — returns `(grey, line_mask)` where `line_mask`
      is a boolean array containing one closed elliptical bubble outline with a `glyph_row`
      inside it, plus a patch of irregular-height hatching outside it (the negative case
      D-23's filters must reject), and `grey` is the uint8 inverse (255 = paper, 0 = ink).
    - `boundary_crossing_page(width=600, height=400)` — returns
      `(grey, line_mask, panel_boxes)` where `panel_boxes` is a list of two
      `(x, y, w, h)` tuples for two framed panels separated by a vertical gutter, and one
      closed bubble outline straddles that gutter so its pixels fall inside BOTH panel
      boxes. This is the fixture success criterion 4 names ("not only on a clean test page").

    Every builder returns freshly allocated arrays (no module-level mutable state) and takes
    no filesystem path. Give the module a docstring explaining it exists so `tests/test_bubbles.py`
    and `tests/test_trappedball.py` share one definition of "a page with a bubble" rather than
    each inventing one.

    Extend `tests/test_web/conftest.py` with a `page_in_project` fixture that depends on
    `client` and `make_png`: it POSTs a volume via `/api/volumes/`, uploads a single PNG page
    via `/api/pages/` with that `volume_id`, and yields the resulting page dict (including
    its `id`, `width`, `height`). Follow the existing file's convention of importing
    `comiccolor.web` symbols inside the fixture body, not at module level.
  </action>
