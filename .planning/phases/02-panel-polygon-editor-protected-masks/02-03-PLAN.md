<objective>
Move `ProtectedMask` from panel scope to page scope, give it the editable vertex polygon and
the `touched` flag the editor's interaction contract needs, and add the panel/protected CRUD
the new routes will call.

Purpose: D-20 is the reason a bubble straddling two panels is representable at all, and
success criterion 4 demands exactly that page. UI-SPEC §3's "touched" state (dashed outline
while detector-proposed, solid once the artist has reshaped or hand-drawn it) needs a field to
key off — this plan is where that field is decided and created.

Output: the data model and persistence layer for the whole phase. Every route plan calls into
this.

Implements D-20 (page scope, clip at use) and supports D-19 (delete is routine — the store
must make delete a one-call operation, not a multi-step reconciliation).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route handler → `Store` | Artist-supplied ids and vertex lists reach SQL parameters |
| pre-Phase-2 database file → `Store.__init__` | A stale local file can present a schema that no longer matches the code reading it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-06 | Tampering | `Store.__init__` against a stale dev database | mitigate | `PRAGMA table_info(protected_mask)` guard raises a `RuntimeError` naming the file and the fix, because `CREATE TABLE IF NOT EXISTS` would otherwise leave the old `panel_id`/`mask_path` shape in place and later writes would target columns that no longer carry their old meaning |
| T-2-14 | Tampering | SQL construction in new CRUD methods | mitigate | Every new method uses parameterized `self._execute(sql, params)`; no f-string or concatenated SQL, and no query string leaves this module (routers call methods, never SQL) |
| T-2-02 | Information Disclosure | `panel_by_id` / `protected_mask_by_id` returning a row from a different project | transfer | Ownership is enforced one layer up, at the route boundary, by `_get_owned_panel`/`_get_owned_protected_mask` (plan 02-05), because `Store` is already scoped to one project's database file by `get_store` |
| T-2-15 | Denial of Service | `update_panel_polygon` bbox recompute on an empty polygon | mitigate | The method raises `ValueError` on a polygon with fewer than 3 vertices rather than computing `min()` over an empty sequence; the HTTP layer rejects such bodies before this point (plan 02-05) |
</threat_model>
