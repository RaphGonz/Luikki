<objective>
Build the bubble detector the artist never has to trust: D-22's own algorithm — detect the text,
flood the white around it, cap the area, discard text that is not sitting in white — implemented
with the OpenCV primitives already vendored, and traced into an editable polygon so the artist
can reshape whatever it got wrong.

Purpose: PROT-01. The detector's job is to save keystrokes, not to be right (D-19's framing
applied to masks) — every failure mode here is recoverable by hand-drawing (PROT-02), which is
why D-24 can defer SFX proposal entirely and D-25 can reject every licence-encumbered learned
detector without costing the artist anything.

Output: `segmentation/bubbles.py`, consumed by the `protected` stage runner in plan 02-07.

Implements D-22, D-23, D-24 (bubbles only — no SFX proposal path is built), D-25 (no learned
model, no bundled weights, no new dependency).
</objective>

  <action>
    Create `src/comiccolor/segmentation/bubbles.py`. Module docstring references `§1.2` and
    states D-22's algorithm in four numbered steps and D-23's rationale (text *detection*, not
    OCR — the characters are never read, only located, so there is no OCR engine, no language
    pack and no licence question). Record D-25 in the docstring: learned detectors were
    surveyed and rejected on licence, not quality, and if one is ever added it belongs behind
    an optional seam distributing no restricted weights. Record D-24: SFX gets no automatic
    proposal — a glyph cluster with no enclosing white to fill produces nothing here by
    construction, and PROT-02's hand-drawing covers SFX completely.

    Imports: `from __future__ import annotations`, `dataclasses.dataclass`, `cv2`, `numpy as np`.
    No new dependency. Do not import `torch`, `scipy` or anything from `third_party/`.

    `@dataclass class BubbleParams` with these fields, each carrying an inline comment naming
    the tradeoff (never a bare literal in a function body):
    - `min_glyph_height_frac: float = 0.4` and `max_glyph_height_frac: float = 2.5` — the band
      around the page's median small-component height a glyph must fall in.
    - `max_glyph_aspect: float = 4.0` — rejects long straight runs (panel frames, speed lines)
      that happen to be short in one dimension.
    - `min_glyphs_per_cluster: int = 3` — a lone blob is dirt, not lettering; this is the
      "bounding-box clustering to drop lonely boxes" step the Rabbit1010 precedent names.
    - `cluster_dilate_px: int = 15` — merges the lines of one text block so a bubble is filled
      once from its whole text block rather than once per character.
    - `max_area_frac: float = 0.35` — D-22 point 3's cap. Comment must say this is `[ASSUMED]`
      per 02-RESEARCH.md A3 and needs tuning against real project pages: too low silently
      discards large legitimate bubbles, too high lets an unclosed bubble leak along a gutter.
    - `min_area_frac: float = 0.001` — a fill smaller than this is a hole in the ink, not a bubble.
    - `max_bubbles: int = 64` — a hard ceiling on returned masks, so a pathological page cannot
      produce an unbounded list.
    - `epsilon_frac: float = 0.01` — `approxPolyDP` tolerance as a fraction of contour
      perimeter, never a fixed pixel constant (Pitfall 1). Comment must say `[ASSUMED]` per A2.

    `_glyph_candidates(line_mask, params) -> np.ndarray`: `cv2.connectedComponentsWithStats`
    on `line_mask.astype(np.uint8)` with `connectivity=8`; compute the median component height;
    keep components whose height falls in the `[min_glyph_height_frac, max_glyph_height_frac]`
    band around it AND whose width/height ratio is under `max_glyph_aspect` AND whose height/width
    ratio is under `max_glyph_aspect`. Returns a boolean mask. Docstring states D-23's claim
    explicitly: these filters reject hatching because hatching has irregular heights and no
    shared baseline.

    `_glyph_clusters(glyphs, params) -> list[np.ndarray]`: dilate `glyphs` by a
    `cluster_dilate_px` square kernel, run `cv2.connectedComponents` on the result, and return
    one seed mask per cluster (`cluster_label == i` intersected with `glyphs`), dropping any
    cluster containing fewer than `min_glyphs_per_cluster` original glyph components.

    `detect_bubbles(grey, line_mask, params=None) -> list[np.ndarray]`: normalise
    `params = params or BubbleParams()`. For each cluster seed, pick a seed point on the paper
    immediately adjacent to the glyph cluster (not a glyph pixel itself — the glyph pixel is ink
    by construction, so flooding from it fills nothing). Flood-fill the non-ink region using
    the flag combination verified in Task 1. Discard the fill when its area is above
    `max_area_frac * height * width` (D-22 point 3, the unclosed-bubble leak) or below
    `min_area_frac * height * width`. Discard when the surrounding ground is not locally
    uniform light — compute the mean of `grey` over the filled region and reject when the
    filled region's mean brightness is below a mid-grey threshold, which is D-22 point 4's
    "text sitting on artwork or a coloured area". De-duplicate: two clusters inside one bubble
    must not yield two identical masks — track filled pixels across iterations and skip a
    cluster whose seed is already inside an accepted fill. Stop at `max_bubbles`. Return the
    list of boolean masks in page space, same shape as `line_mask`.

    `mask_to_polygon(mask, epsilon_frac=0.01) -> list[tuple[int, int]]`: `cv2.findContours`
    with `RETR_EXTERNAL` and `CHAIN_APPROX_SIMPLE`; return `[]` when there are no contours;
    take the largest by `cv2.contourArea`; `epsilon = epsilon_frac * cv2.arcLength(largest, True)`;
    `cv2.approxPolyDP`; return a list of `(int, int)` tuples. Return `[]` when the simplified
    contour has fewer than 3 points, so a degenerate trace never reaches the store as an
    unrenderable polygon.

    Every threshold comparison reads a `BubbleParams` field. No magic numbers in function bodies.

| T-2-05 | Denial of Service | `detect_bubbles` flood fill on a pathological page | mitigate | `max_area_frac` caps any single fill at 35% of page area and `max_bubbles` caps the returned list at 64; a page of dense noise produces a bounded amount of work and a bounded result, never an unbounded mask list |
| T-2-16 | Denial of Service | `mask_to_polygon` producing an enormous vertex list | mitigate | `epsilon_frac` is perimeter-relative so vertex count scales with shape complexity, not resolution; the HTTP layer additionally caps stored polygons at 512 vertices (plan 02-05), and a sub-3-vertex trace returns `[]` |
| T-2-17 | Denial of Service | Bubble detection blocking the request thread | transfer | Handled at the route/runner layer in plan 02-07: detection is wrapped so a failure still advances the stage and returns a non-blocking banner (02-RESEARCH.md Pitfall 6).
