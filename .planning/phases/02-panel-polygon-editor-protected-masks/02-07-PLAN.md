<objective>
Fill the first two `runner=None` holes Phase 1 left in the stage registry: `panels` detects and
persists four-vertex panel polygons in reading order, `protected` detects bubbles and persists
them as editable masks. Both are the first stages after `import` to become genuinely live.

Purpose: PAN-01 and PROT-01 are stage outputs, not route outputs — the artist's editor reads what
these produced. D-11's "declared but unimplemented" state, which Phase 1 shipped deliberately,
ends here for two of eight stages.

Output: two `StageRunner`s and their registry wiring.

Implements D-17 (box seed, never a traced contour), D-18 (the lowered floor is what makes
borderless panels reach the artist at all), D-22 (the detector runs here), D-24 (every proposed
mask is `kind=bubble`; nothing proposes SFX), D-21 (protected geometry is persisted page-scoped,
rasterised only at use).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored `page.source_path` → filesystem read | A database-held relative path is joined to the project folder and opened |
| uploaded page raster → detection pipelines | Arbitrary artist-supplied image content drives OpenCV work inside a request thread |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-25 | Tampering | `store.path.parent / page.source_path` join | mitigate | `source_path` is server-generated at upload time (Phase 1's `uploads.py` display_name/save_upload split, T-01-PATH) and never client-supplied; the runner resolves it exactly the way `get_page_image` already does rather than inventing a second resolution path, and a missing file raises `FileNotFoundError` rather than proceeding |
| T-2-17 | Denial of Service | Bubble detection inside a request thread | mitigate | `BubbleParams`' `max_area_frac` and `max_bubbles` bound the work and the result (plan 02-04); `BubbleDetectionFailed` gives the route a way to return promptly instead of hanging. Page-scale OpenCV stays inside a normal synchronous request per Phase 1's convention — a job queue is Phase 4's problem, not this one's |
| T-2-26 | Denial of Service | Re-running a runner accumulating rows | mitigate | Both runners delete the page's existing rows before writing, so repeated confirms cannot grow the table without bound; tested by the idempotence assertions |
| T-2-27 | Tampering | A runner advancing the page past its own gate | mitigate | Neither runner touches `page.stage`; a test asserts this, preserving D-10's "declares, never orchestrates" property that the whole forward-only gate model rests on |
</threat_model>
