<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server-computed cost sentence → artist's consent | The artist authorises a destructive action based entirely on strings this dialog displays |
| Go-Back confirmation → bulk deletion | One click destroys every protected mask on the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-41 | Tampering | A dialog showing a cost that does not match what is deleted | mitigate | The component holds no copy of its own — asserted by a grep for the sentence fragments — so the only strings shown are the ones plan 02-11 computed from the same reads its delete acts on |
| T-2-08 | Information Disclosure | Dialog copy leaking internals | mitigate | The dialog renders only `GoBackTargetDto` fields, which are assembled server-side from integer counts and `Stage.display_name`; no path or exception text can reach it |
| T-2-09 | Tampering (XSS) | Server strings in the dialog | mitigate | Every string is set with `textContent`; `innerHTML` is forbidden and asserted absent |
| T-2-42 | Denial of Service | Double-confirming a Go-Back | mitigate | The confirm button disables while `onConfirm` is in flight; a jsdom test asserts a double-click calls it once |
| T-2-43 | Tampering | Replaying a stale undo op against rows a Go-Back deleted | mitigate | Both undo stacks are cleared on a successful Go-Back, so no inverse can reference a deleted row id |
| T-2-44 | Repudiation | The destructive action being the default focus | mitigate | Focus lands on the cancel button on open; the confirm button is destructive-coloured and labelled with the concrete verb and cost, never "Yes" or "OK" |
</threat_model>
