<objective>
Make Phase 1's confirmation gate and Go-Back contracts real for the first time. Three routes:
confirm the current stage, ask what going back would cost, and go back.

Purpose: D-06/D-07 (forward-only, one gate per stage per page) and D-08 (going back is costed and
explicit) were specified in Phase 1 and deliberately left unreachable because only Import existed.
Panels and Protected are the first two stages a Go-Back target can point at, and 01-UI-SPEC.md §3
is explicit that a Go-Back with no computable number must simply not be offered — so the cost
sentence has to be computed here, on the server, from real counts.

Output: the three gate routes and their tests.

Implements D-19 indirectly (the Panels gate's zero-panel refusal is what makes routine deletion
safe at the stage boundary) and D-24 (the Protected gate is never blocked by mask count — a
splash page with no dialogue is valid, and SFX are the artist's to draw).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → stage transition routes | A client request moves a page through the forward-only pipeline and can destroy an arbitrary amount of the artist's work |
| server-computed cost sentence → artist's decision | The artist consents to a destructive action on the basis of a number this code produces |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-34 | Tampering | Go-Back destroying more than the artist agreed to | mitigate | The discarded counts in the returned sentence are computed from the same `panels_for_page`/`protected_for_page` reads the delete then acts on, and the route deletes exactly the categories the sentence named — asserted by tests that check both the string and the resulting row counts |
| T-2-35 | Tampering | Skipping stages or moving backwards through the confirm route | mitigate | `confirm_stage` advances by `next_stage(page.stage)` only — one step, never a client-supplied target — and `go_back` refuses any target not strictly earlier in `STAGES` with 409 |
| T-2-08 | Information Disclosure | Go-Back sentence leaking internals | mitigate | Every sentence is assembled from integer counts and `Stage.display_name` only; no filesystem path, page path or exception text reaches it |
| T-2-17 | Denial of Service | Bubble detection blocking the confirm request | mitigate | `BubbleDetectionFailed` is caught and returned as a banner, so the request always completes and the artist always reaches their own drawing tools; `BubbleParams`' caps bound the work itself (plan 02-04) |
| T-2-36 | Denial of Service | Repeated confirm/go-back cycles accumulating rows | mitigate | Both runners delete before writing (plan 02-07) and `go_back` deletes explicitly, so a confirm/go-back loop is bounded |
| T-2-02 | Tampering / Information Disclosure | `page_id` in the path | mitigate | `get_owned_page` on every route; unknown or foreign ids answer 404, tested including the `blank_client` no-project case |
| T-2-04 | Spoofing | Cross-origin stage transition | mitigate | Inherited: `page.router` is registered inside `create_app()` under `/api/pages` behind `_reject_foreign_origins` |
</threat_model>
